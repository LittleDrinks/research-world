# Report Publication
Research Kernel owns report publication. `publish_report` accepts only a human-readable title and derives every finding, citation and evidence block from admitted Kernel state. Runtime contributes no facts, links, HTML or Artifact input.
`report_projection` returns either `{status: ready, projection, contract}` or `{status: blocked, gaps, contract}`. A ready projection has exactly `question`, `facts`, `claims`, `sources` and `artifacts`. Its allowlist is canonical Claim, evidence and Artifact ids; supported fact text; source title, source-level enum and normalized check time; Artifact kind, byte size and exact Claim/evidence links. Project question, Claim text and source title pass the same narrative safety policy. Raw Node payload keys, node kinds, custom Claim ids, MIME strings, anchors, paths, Artifact bytes, configuration, credentials, transport and Trace fields do not cross this boundary.
The projection budget is 2,048 approximate tokens, calculated from admitted raw input before public or private delivery data is materialized. Overflow yields only the fixed contract, a numeric token count and stable gap code. It never truncates or returns a partial projection.
The private publication model starts from a ready public projection. It loads only each allowlisted Artifact id and accepts a display block only when stored id, recognized kind and size match that public record. Artifact ownership is direct: a Claim may reference only admitted `source` or `experiment` evidence, and an Artifact link names that exact Claim and evidence id; `source_id` appears only for source-owned evidence. Renderer-created anchors cover every cited source and experiment, so no Artifact is flattened across Claims.
Code is `text/plain` or `text/x-*`; formulas are `application/x-latex` or `text/x-tex`; charts are PNG, JPEG, GIF or WebP. Code and formulas require bounded UTF-8 text that passes the sensitive-data policy and are HTML-escaped. A verified chart is decoded, materialized as a fresh RGBA pixel surface, then emitted only as a bounded static PNG data image; visual alpha survives, while input palettes, metadata and trailing bytes do not. SVG, HTML, unsupported types, invalid UTF-8, oversized content, mismatched metadata and unsafe text produce a controlled validation failure. Renderer creates tags, attributes and data URLs itself; raw Artifact content is never trusted as HTML.
Rendered-output validation is independent of evidence admission. It validates document structure, generated active content after HTML entity expansion and the sensitive-data policy without decoding escaped code into markup. Its safety input removes only a structurally recognized `<img src>` value that is byte-for-byte the renderer-produced, canonical re-encoded static PNG chart payload. Every other `data:` URI, including percent-encoded payloads, produces the `data_uri_exposed` output-validation gap; active URLs and text remain scanned. Thus a code literal containing tag-shaped text remains evidence, while credential, URL, path and Trace-shaped values cannot enter the report.
Publication stages are ordered Kernel facts: `projection`, `citation_validation`, `rendering`, `output_validation`, `persistence`. A completed stage has `status: completed`; the first stopped stage has `status: failed`; later stages are absent. A Kernel `{status: failed}` is a failed ACP and report lifecycle: no completed announcement, preview, download or save. Persistence publishes the HTML Artifact and record as one visible unit. Successful publication and save return the record constructed for their committed INSERT path, never a post-commit readback. A persistence failure reports its controlled stage and creates no publication or saved-version record; an unreferenced content-addressed object may remain storage-internal.
World owns persisted records. Successful publications are `report_publications {id, project_id, thread_id, title, artifact_id, created_at}`; named immutable references are `reports {id, project_id, thread_id, publication_id, title, artifact_id, created_at}`. Both are ordered by `created_at DESC, id DESC`. Thread detail exposes publication cards only as `{id, thread_id, title, created_at}` and named cards only as `{id, publication_id, title, created_at}`; records are never inferred from arbitrary Artifacts.
Runtime projects trusted `publish_report` results from Trace into complete chat messages. It announces only this tool through ACP with a fixed Chinese title, a fresh report call id and `in_progress` then `completed` or `failed` status; it sends no arguments, content, raw output or Trace fields. Report events retain their Trace turn and sequence, so chat interleaves them chronologically with messages; it merges persisted publication cards by publication id, retains failures, and restores the same preview/download affordances after reload or Session restart. A successful publish or save remains visible when its best-effort detail refresh fails.
Thread detail projects persisted publication records as the reload authority. Each report card and operation owns a request sequence, so an unrelated save cannot stale a retry while an older response for the same card remains stale. Detail refresh owns a separate Thread sequence, and only its newest response may replace Thread detail. A successful retry replaces its originating Trace result with its publication instead of adding a second card. A confirmed HTTP publication remains a successful card with preview and download when refresh fails; refresh state is controlled separately and cannot turn a 201 result into failure or trigger a second publication. ACP report tool updates remain visible in chronological chat flow until authoritative Thread detail replaces them. Failed stages are rendered only from the ordered Kernel stage sequence.
The report structure is fixed: `Research question`, `Conclusions`, `Evidence and methods`, `Limitations and gaps`. The research-report Skill reads only a ready envelope, reports controlled blocked gaps without composition, and delegates headings, citations, evidence rendering and HTML to Kernel.
Validated HTML is one complete balanced document: one doctype, html/head/body in order, one nonempty title, no trailing data, comment, processing instruction, declaration or CDATA, and the fixed semantic headings, table, citations and evidence structure. `latex2mathml==3.81.0` converts accepted TeX to MathML; every library-defined malformed-input exception is a controlled validation failure and the renderer never parses TeX itself. `Pillow==12.3.0` verifies integrity then decodes chart pixels; declared PNG, JPEG and WebP formats must match, while animated charts are rejected. Malformed, truncated, decompression-bomb, excessive-dimension or excessive-pixel images are controlled validation failures.
Persistence serializes competing publication calls by project Artifact id, but neither that lock nor prior content presence proves sole ownership against Artifact capture. A failed publisher never discards a content-addressed object. Artifact files alone never project as publication or saved-version state. Failed publication returns HTTP 422 with the ordered Kernel failure stages and retryable assessment; only `published` returns 201. The API client parses that failure envelope for the retry UI. ACP progress remains visible until Thread detail replaces it; a refresh failure leaves that state visible and exposes the normal Thread refresh failure behavior. Benchmarks construct admitted Kernel state at 2,048 and 2,049 input tokens and inspect validator-approved persisted content; browser tests read immutable saved-version content and cover publication, preview, download, save, failed retry and refresh failure.
Formula output is parsed as XML before HTML rendering. Every element and attribute uses the fixed MathML namespace and converter allowlist; mathematical text such as `a:b`, `x:=y` and `mphantom` is accepted, while URI-like text and foreign namespaces, attributes or elements are rejected as controlled rendering failures.
HTTP Thread paths are authoritative. Publish accepts exactly `title`; save accepts exactly `title` and `publication_id`; content is bodyless `GET` with optional `download=true`. Kernel resolves Project from the path Thread, rejects extra fields and has no legacy endpoint fallback. Preview is sandboxed and download uses `text/html`.
